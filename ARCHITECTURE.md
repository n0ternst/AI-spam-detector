# Описание архитектуры и формата входных и выходных данных (DW-1)

## 1. Архитектура конвейера обработки

Модуль **Email AI Detector (DW-1)** представляет собой двухэшелонный конвейер анализа электронных писем формата RFC 5322 (`.eml`) с механизмом позднего слияния оценок (Late Fusion).

```text
Входящее письмо (.EML / Каталог / JSONL)
      │
      ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Разбор MIME-структуры (core/parser.py)                              │
│ • Каскадное декодирование кодировок (UTF-8, Windows-1251, KOI8-R)      │
│ • Анализ технических заголовков (X-Mailer, From, Reply-To, DKIM/SPF)   │
│ • Расчёт расхождения версий text/plain и text/html (Jaccard Desync)    │
└───────────┬────────────────────────────────────────────────────────────┘
            │ raw_html + clean_text + headers_meta
            ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2. Эшелон 1: Структурный анализ верстки (core/html_detector.py)        │
│ • Вычисление контрастности текста и фона по WCAG 2.1 (порог < 1.3)     │
│ • Деобфускация CSS, поиск скрытых элементов (display:none, font-size:0)│
│ • Удаление невидимых Zero-Width символов (\u200b)                      │
│ • 46 признаков DOM -> HistGradientBoosting (с изотонической калибровкой│
│   и контекстно-адаптивным порогом)                                     │
└───────────┬────────────────────────────────────────────────────────────┘
            │ Санитизированный visible_text + Оценка риска HTML + AST-дерево
            ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3. Эшелон 2: Анализ текста (core/text_detector.py)                     │
│ • Очистка текста от URL, email-адресов и артефактов разметки           │
│ • Single Forward Pass через Qwen2.5-1.5B-Instruct (GPU bfloat16 / API) │
│ • 15 признаков LLM: Log-Rank, LRR, Fast-DetectGPT (глобально и по      │
│   скользящим окнам из 3 предложений)                                   │
│ • 9 стилометрических признаков (вариативность предложений, TTR и др.)  │
│ • Классификация в двуязычном CatBoost (24 признака: cb_ru / cb_eng)    │
│ • Локализация сгенерированного фрагмента [start_char, end_char]        │
└───────────┬────────────────────────────────────────────────────────────┘
            │ Вероятность ИИ в тексте + Координаты подозрительного участка
            ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 4. Позднее слияние и генерация отчёта (pipeline.py)                    │
│ • Асимметричное объединение оценок (Late Fusion)                       │
│ • Расчёт локальных SHAP-вкладов текстовых признаков                    │
│ • Формирование бинарного вердикта, детального статуса и объяснения     │
│   на русском языке для SOC в формате JSON                              │
└────────────────────────────────────────────────────────────────────────┘
```

### Функциональные модули

1. **`core/parser.py` (MIME-парсер):**
   * Выполняет безопасный разбор вложений и альтернативных частей письма.
   * Вычисляет расхождение Жаккара между текстовой и HTML-версией (`multipart_desync_score`) для нейтрализации атак разделения контента (*Multipart Desync*).
   * Выявляет несоответствие между почтовым клиентом в заголовке `X-Mailer` и фактической версткой (например, спуфинг Outlook при отсутствии служебных MSO-тегов).

2. **`core/html_detector.py` (HTML-детектор):**
   * Извлекает 46 признаков топологии DOM, легаси-атрибутов почтовых клиентов, признаков вставки из веб-интерфейсов LLM (`Söhne`, `--tw-`), нераспарсенного Markdown (`**`, `##`) и стелс-клоакинга.
   * Изолирует скрытые блоки и вычищает Zero-Width символы, отдавая санитизированный текст во второй эшелон, что предотвращает атаку искусственного размытия перплексии (*Perplexity Dilution*).
   * Оценивает риск верстки через `HistGradientBoostingClassifier`, откалиброванный изотонической регрессией.

3. **`core/text_detector.py` (Текстовый детектор):**
   * Формирует 24 признака:
     * **15 признаков модели Qwen2.5-1.5B-Instruct:** глобальные метрики `lr_global`, `lrr_global`, `fd_global`, статистики распределения по окнам (`lr_win_max`, `lr_win_mean`, `lr_win_std`, `lr_win_q90`, `lrr_win_max`, `lrr_win_mean`, `lrr_win_std`, `fd_win_max`, `fd_win_mean`, `fd_win_std`) и метрики наиболее подозрительного спана (`merged_span_lr`, `merged_span_ratio`).
     * **9 стилометрических признаков:** средняя длина предложения `avg_sent_len`, дисперсия длины предложений `sent_len_var`, доля коротких предложений `short_sent_ratio`, лексическое разнообразие `root_ttr`, дисперсия длины слов `word_len_var`, частоты знаков пунктуации (`comma_rate`, `dash_rate`, `excl_quest_rate`, `colon_semi_rate`).
   * Классифицирует вектор с помощью `CatBoostClassifier` (`cb_ru.cbm` для русского языка, `cb_eng.cbm` для английского).
   * Выделяет подозрительный фрагмент `most_ai_chunk` и определяет его символьные границы `[start_char, end_char]` в исходном тексте.

4. **`pipeline.py` (Оркестратор):**
   * Выполняет асимметричное слияние оценок: если верстка письма стандартная и не содержит аномалий, приоритет отдается вероятности текстового ядра; при наличии улик клоакинга или явных артефактов верстки итоговый индекс риска корректируется в сторону блокировки.
   * Вычисляет локальный вклад признаков (SHAP) и генерирует структурированный JSON-отчёт с русскоязычным объяснением.

## 2. Формат входных данных

Конвейер поддерживает три режима ввода через аргументы командной строки:

1. **Одиночный файл письма (`--eml <путь>`):** файл формата RFC 5322 (`.eml`).
2. **Каталог писем (`--dir <путь>`):** пакетная обработка директории с файлами писем (включая файлы без расширения при наличии валидных MIME-заголовков).
3. **Пакетный файл JSONL (`--jsonl <путь>`):** построчный JSON следующей структуры:
   ```json
   {
     "id": "email_001",
     "raw_html": "<html><body><p>Текст письма...</p></body></html>",
     "text": "Резервный текстовый контент",
     "lang": "ru"
   }
   ```

### 3.2. Описание полей отчёта

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `file_id` / `file` | `string` | Имя входного файла письма. |
| `verdict` | `string` | Официальный бинарный вердикт: `"AI-Generated"` (при `ai_score >= threshold`) или `"Human-Written"`. |
| `security_status` | `string` | Статус безопасности для SOC: `"CLEAN_HUMAN"`, `"SOFT_AI_SUSPICIOUS"`, `"STRICT_AI_GENERATED"`, `"SPAM_BLOCKED"`. |
| `ai_score` | `float` | Итоговая нормализованная вероятность генеративного происхождения `[0.0 .. 1.0]`. |
| `risk_score` | `float` | Итоговый уровень угрозы с учетом рисков сокрытия контента. |
| `threshold` | `float` | Порог классификации (по умолчанию: `0.558` для русского языка, `0.658` для английского). |
| `flagged_zones` | `list[str]` | Зоны письма с обнаруженными аномалиями (`body_text`, `html_structure`). |
| `zones.body_text` | `object` | Результаты текстового детектора: вероятность, статус, фрагмент `most_ai_chunk` и границы `char_interval: [start, end]`. |
| `zones.html_structure`| `object` | Результаты HTML-детектора: вероятность, уровень угрозы сокрытия `cloaking_risk`, флаг `is_cloaking_detected`. |
| `explanation` | `string` | Текстовое обоснование на русском языке для аналитика SOC. |
| `key_signals` | `list[obj]` | Список доминирующих признаков с указанием численного значения и локального SHAP-вклада. |
| `details.ast_tree` | `list[obj]` | Дерево блоков письма с отметками видимости и привязкой вероятностей генерации к конкретным узлам. |
